# UX Writing Reference

## Goals

- Help users understand what is happening and what to do next.
- Reduce confusion through specific, concise language.

## Rules

- Prefer specific verbs: `Create project` over `Submit`
- Explain errors in plain language
- Tell users how to recover
- Keep terminology consistent across the product
- Use labels, not placeholders alone

## Good Patterns

- Empty states with a clear next action
- Success messages that confirm what changed
- Destructive confirmations that name the thing being affected

## Avoid

- Jargon without explanation
- Generic messages like `Something went wrong`
- Redundant copy that repeats visible UI
- Humor in stressful error moments unless brand context truly supports it
