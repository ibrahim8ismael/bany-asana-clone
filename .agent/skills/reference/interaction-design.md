# Interaction Design Reference

## Goals

- Make actions feel obvious, fast, and recoverable.
- Reduce user effort through defaults and progressive disclosure.

## Core Rules

- Primary actions should be unmistakable.
- Secondary actions should stay available but quieter.
- Inputs need labels, states, and actionable validation.
- Empty, loading, success, and error states are part of the design.

## Good Interaction Patterns

- Inline validation with helpful correction guidance
- Optimistic updates when safe
- Undo for reversible destructive actions
- Focus states that are clearly visible

## Avoid

- Too many primary buttons
- Hidden critical actions on hover only
- Dead-end empty states
- Generic error messaging with no next step
